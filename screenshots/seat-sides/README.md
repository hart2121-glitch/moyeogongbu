# 1·3·4·6번 좌우 이동 검토

각 좌석에서 왼쪽(x=0.315)과 오른쪽(x=0.76)의 같은 높이 바닥으로 나간 뒤 다시 착석하는 총 8가지 시나리오입니다. 단순 좌석 1→6 순회와 별도로 실행합니다. 테스트: `npm test` 또는 개발 서버 실행 후 `node --test tests/seat-sides-browser.test.mjs`.

- 의자에서 일어설 때 수직 진입선을 먼저 되짚고, 통로를 통해 좌우 목적지로 이동한 뒤 다시 착석합니다.
- 모든 경로 구간을 선분/장애물 교차로 검사하고, 실제 이동 프레임에서도 같은 검사를 적용합니다.
- 브라우저에서는 16ms마다 발 좌표와 이미지 표시 상태를 수집해 파티션 경계 + 가로 14px/세로 1.5px의 발 여유 침범을 검사합니다. 결과와 수집 횟수는 `results.json`에 있습니다.
- 렌더링 크기는 직전보다 10% 확대됐고 원본 비율·발 기준점을 유지합니다. 실제 방향별 발 x 위치를 맞추기 위해 이미지를 표시할 때만 수평 이동합니다.
- 움직이는 캐릭터 전체를 가구 뒤로 숨기지 않습니다. 미리 로드한 방향 이미지 중 해당 방향을 표시하며, 착석 시 기존 책상·모니터 전경 가림은 유지합니다.

## 실제 장애물 변경 범위

좌표는 원본 1705×922 기준이고 코드에서는 상대 좌표로 변환합니다.

| 좌석 | 왼쪽 파티션 x | 오른쪽 파티션 x | 파티션 y |
|---|---|---|---|
| 1 | 571~603 | 781~813 | 405~558 |
| 3 | 1005~1037 | 1227~1255 | 405~558 |
| 4 | 571~603 | 781~813 | 563~724 |
| 6 | 1005~1037 | 1227~1255 | 563~724 |

기존보다 파티션 x 영역을 양옆 4px씩 넓히고, 경로 탐색에서 발 폭의 반인 14px를 추가로 피합니다. 2·5번이 공유하는 파티션도 같은 규칙입니다. 전체 머리카락/신체 실루엣의 픽셀 충돌은 아니며 발 중심·발 폭 기준입니다.

## 최종 실행 결과

`npm run build` 성공, `npm test` 24개 통과(실패·건너뜀 0). 집중 브라우저 검사에서 2,803회 좌표를 수집했고 발 폭의 파티션 침범 및 표시 이미지 누락은 0회였습니다. 기존 6개 좌석 순회와 휴식·복귀·화장실·퇴근도 통과했습니다. 기존 탭 간 예약 경쟁 조건은 원자적 IndexedDB 저장으로 보완하고 10회 동시 예약 테스트를 통과했습니다.
