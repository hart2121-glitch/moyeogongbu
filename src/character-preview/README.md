# 개발용 캐릭터 레이어 미리보기

접속: 기존 미리보기 주소의 경로를 `/character-preview.html`로 바꿉니다. 게임을 그대로 열어 두려면 새 탭에서 접속하세요. Vite 개발 서버와 `npm run build` 결과 모두 이 HTML 진입점을 제공합니다.

1. 정면·후면·왼쪽·오른쪽 중 비교할 방향을 고릅니다.
2. 뒷머리, 기본 몸, 의상, 얼굴, 앞머리, 액세서리에 실제로 분리한 PNG를 선택합니다.
3. 각 `표시` 체크로 레이어를 켜고 끄며 왼쪽의 기존 완성형 이미지와 비교합니다.
4. 잘못 고른 파일은 `파일 제거`, 모든 방향을 비우려면 `전체 비우기`를 누릅니다.

모든 레이어는 원본 87×110px 투명 PNG이며 캔버스의 (0,0)에 겹칩니다. 큰/작은 이미지를 자동으로 자르거나 늘리지 않습니다. PNG 시그니처·실제 크기·투명 픽셀을 검사하고 잘못된 교체 파일이면 기존 레이어를 유지합니다. 방향별 파일은 따로 보관하고 체크 상태는 공통입니다.

처음에는 합성 영역이 완전히 비어 있습니다. 현재 완성형 PNG는 비교에만 사용하며 임의로 자르거나 완성된 레이어라고 등록하지 않습니다. 파일은 이 탭 메모리의 Blob URL로만 읽습니다. 서버 업로드·localStorage·IndexedDB·게임 장착 상태에 쓰지 않으며 새로고침하면 사라집니다. 제거·교체·전체 비우기·화면 종료 때 URL 자원을 해제합니다.

## 확장 경계

- `model.js`: 캔버스 규격, 뒤→앞 순서, `schemaVersion`, `itemId`, `paletteId`, `action.direction.frame` 키.
- `LayerStack.jsx`: 공통 자세 키에 해당하는 에셋만 같은 캔버스에 합성. 위치/확대는 부모에서 한 번 적용합니다.
- `loadLayer.js`: 파일 검증과 로딩. 실제 PNG를 변경하지 않습니다.
- `main.jsx`: 미리보기만의 상태와 조작. 게임 모듈이나 저장소를 가져오지 않습니다.
- `preview.css`: 이 HTML에서만 사용하는 스타일. 기존 게임 CSS는 수정하지 않습니다.

현재 UI는 `idle`의 4방향, 프레임 0만 제공합니다. 동작·프레임 키와 팔레트 ID는 미래 확장을 위한 구조이며 현재 애니메이션 재생·염색·상점 연결 기능이 있다는 뜻은 아닙니다. 추후 한 개의 공통 시간축에서 프레임을 선택하고, 팔레트 처리된 부품을 로더 단계에서 준비할 수 있습니다. 게임 적용은 별도 작업입니다.

## 검증

개발 서버 실행 후 `node --test tests/layer-preview.test.mjs`. 테스트용 단색 사각형 PNG는 메모리에서만 생성하며 실제 캐릭터 레이어로 제공하지 않습니다. 화면 픽셀을 읽어 레이어 순서·토글 결과를 확인하고 파일 검증·방향별 분리·상태 격리를 검사합니다.
