**한 줄 소개:** 친구들과 도트 그림 회사 사무실에 출근해 각자 자리에 앉아 공부하고, 공부한 시간만큼 시급처럼 받은 코인으로 캐릭터와 책상을 꾸미는 PC 웹 앱.

## 핵심 흐름
- 친구 방에 입장해 내 자리에 앉으면 공부 시간 측정이 시작된다 (원하면 뽀모도로).
- 앉아 있는 동안 1분에 1코인이 쌓이고, 같은 방 친구의 상태와 공부 시간이 보인다.
- 퇴근하면 "오늘의 정산"을 받고, 코인으로 캐릭터와 내 책상을 꾸민다.
- 다음 날 꾸민 내 자리와 친구들이 기다리는 방으로 다시 출근한다.

## 사용자 목표: "제대로 동작한다"의 기준
- 한 세션은 출근(입장) → 착석 → 공부 → 퇴근 정산으로 끝날 때 완성된다. 정산된 시간과 코인이 계정에 남고, 친구 화면에도 같은 상태가 보여야 한다.
- 실패 상태는 없다. 대신 자리 비움은 부드럽게 확인하고 공부 시간에서 뺀다.

## MVP
1. Google 로그인과 계정 (Supabase), 친구 코드, 계정 삭제
2. 실시간 6석 회사 방: 입장, 이동, 착석, 상태와 반응 공유, 좌석은 서버가 판정
3. 공부 세션: 착석 자동 측정, 뽀모도로 선택, 자리 비움 확인
4. 시급 코인과 퇴근 정산
5. 공부 기록 화면 (오늘, 7일, 잔디 달력)과 날짜별 할 일
6. 친구 (코드 추가, 요청 수락과 거절, 차단, 상태 보기)와 우편함, 알림
7. 상점과 캐릭터 레이어 꾸미기

## 범위 밖
- 랭킹, 친구 간 비교, 경쟁 요소
- 자유 텍스트 채팅, 음악 (백색소음만)
- 공용 스터디카페, 학교 테마 (첫 출시 이후)
- 모바일 화면 (PC 웹 1280px 이상 우선), 게스트 모드
- 자유 배치 방 꾸미기 (슬롯 방식만)

## 빌드 순서
1. 구조 정리: TypeScript 점진 전환, React용 MVVM, 기능 단위 폴더, 라우팅 (로비 겉모습은 그대로)
2. Supabase 기반: 개발과 운영 프로젝트, 마이그레이션, Google 로그인, CI 테스트
3. 세션과 시급: 착석 측정, 자리 비움, 뽀모도로, 정산 (지금 그림 위에서)
4. 실시간 방: 좌석 서버 판정, 목적지 기반 이동 동기화, 상태와 반응
5. 기록, 할 일, 친구, 우편함, 알림
6. 상점과 캐릭터 꾸미기 (새 픽셀아트 캐릭터가 준비되는 대로)
7. 새 픽셀아트 방으로 교체한 뒤 방 꾸미기 슬롯

아트 제작은 1~5와 같은 기간에 진행한다.

---
**누구를 위한, 어떤 느낌:** 혼자 공부하기 힘든 취준생, 대학생, 수험생이 "친구와 같이 출근해서 일하는" 느낌으로 꾸준히 앉아 있게 되는 것.

**아트와 오디오 방향:** 메이플스토리 수준의 2D 도트 스프라이트로 그린 아늑한 회사 사무실, CC0 백색소음 (비, 카페, 키보드).

**참고 제품:** Gather Town의 "같은 공간에 있는 감각" 중 6석 방 하나만, 열품타의 공부 시간 측정 중 개인 기록만 가져온다. 경쟁과 순위는 가져오지 않는다.

# 합의된 세부 결정

## 세션과 보상
| 항목 | 값 |
|---|---|
| 측정 시작과 정지 | 좌석 착석 시 시작. 휴식, 화장실, 퇴근 시 정지. 위로 세는 방식 |
| 뽀모도로 프리셋 | 25분 공부와 5분 휴식, 50분 공부와 10분 휴식, 직접 설정 (공부 시간 20~60분) |
| 뽀모도로 휴식 | 알림과 "휴게실로 가기" 버튼. 캐릭터는 자동 이동하지 않음. 휴식 중에는 앉아 있어도 공부 시간에서 제외 |
| 자리 비움 | 앱 페이지 안에서 60분 동안 입력이 없으면 안부 같은 체크인. 5분 무응답이면 휴식 전환, 그 시간 제외. 뽀모도로 중에는 종료 알림 응답이 체크인을 대신함 |
| 하루 기준 | 한국 시간 오전 5시에 리셋. 경계를 넘는 세션은 두 날짜로 나눠 기록 |
| 동시 접속 | 계정당 세션 하나. 새 탭이나 기기가 넘겨받고 이전 화면에 안내 |
| 시급 | 60코인 (1분당 1코인). 초 단위로 쌓고 다 찬 1분마다 지급, 남은 초는 그날 안에서 이월 |
| 하루 상한 | 10시간 (600코인). 초과 시간은 기록만 |
| 뽀모도로 완주 보너스 | 5코인. 공부 시간 20분 이상인 사이클만, 하루 최대 10회 |
| 할 일 완료 | 개당 2코인, 하루 최대 10개. 완료 취소 시 회수 |
| 정산 표시 | 회사 방 안에서만. 툴바에 오늘 근무 시간과 코인, 퇴근 시 "오늘의 정산" 카드. 퇴근 없이 닫았으면 다음 로그인 때 로비 위 일회성 팝업으로 가장 최근 하루의 "지난 정산". 로비 고정 요소는 코인 숫자만 |

모든 수치는 설정 파일로 분리한다.

## 방과 친구
- 방은 6석 고정, 멤버와 동시 인원도 최대 6명. 코드로 들어온 방은 내 방 목록에 남는다. 한 사람당 방 3개까지 만들 수 있다.
- 방장은 이름 변경, 초대 코드 재발급, 강퇴. 강퇴된 사람은 방장이 풀어 주기 전까지 재입장 불가.
- 연결이 끊기면 측정을 멈추고, 2분 안에 돌아오지 않으면 좌석을 푼다.
- 같은 방 공유: 머리 위 이름표, 마우스를 올리면 상태와 오늘 공부 시간과 "지금 하는 일" (공개 선택). 반응은 이모지 6개와 응원 문구 3개, 3초 표시, 5초 간격.
- 내부 식별은 Supabase 계정 UUID. 친구 추가는 계정마다 고정된 8자 친구 코드, 또는 같은 방에서 캐릭터를 눌러 추가. 재발급 없음, 요청 거절과 차단 제공.
- 친구는 최대 50명. 끊기는 조용히, 차단하면 관계도 끊기고 설정에서 해제 가능. 같은 방 멤버가 아닌 친구에게는 방 이름 대신 상태만 보인다.
- 방 멤버는 누구나 친구에게 방 초대를 보낼 수 있다 (가득 찬 방 제외).
- 출석 보상: 하루 첫 착석 때 10코인을 우편으로. 연속 출석 보너스 없음.
- 우편함: 친구 요청, 방 초대, 시스템 보상. 30일 뒤 자동 삭제. 알림: 친구 입장, 뽀모도로 종료, 자리 비움 확인. 브라우저 알림은 허용한 경우 뽀모도로와 자리 비움만.

## 기록과 할 일
- 공부 기록: 오늘 시간과 코인, 최근 7일 막대그래프, 1년 잔디 달력 (5단계: 0분, 1시간 미만, 1~3시간, 3~6시간, 6시간 이상). 날짜를 누르면 그날 상세. 본인만 볼 수 있고 친구 비교 없음.
- 할 일: 날짜별, 하루 30개, 1~50자. 새 날에 어제 미완료를 제안해 모두 또는 골라 가져오기. 세션에 연결해 "지금 하는 일" 표시.

## 꾸미기와 상점
- 캐릭터 레이어: 몸, 얼굴, 뒷머리, 앞머리, 의상, 액세서리.
- 방 꾸미기는 슬롯 방식. 공용 공간 (벽, 창가, 휴게실)은 방장, 책상 위는 그 자리 주인. 남의 책상은 꾸밀 수 없고, 친구가 앉아 있으면 그 친구가 꾸민 책상이 보인다.
- 책상 꾸밈은 사람을 따라다니는 "내 책상 세트"다 (슬롯 4개). 어느 회사 방 어느 자리에 앉든 내 세트가 펼쳐지고, 빈 자리는 기본 책상이다. 내 방 책상에도 같은 세트가 놓인다 (2026-10-31 결정).
- 로비(집, 내 방)에도 꾸미기 슬롯을 둔다: 커튼, 벽 액자, 벽 선반, 침대 이불, 러그, 화분, 그리고 책상 (2026-10-31 결정). 슬롯 위치와 그림 요구사항은 `design/quick-specs/room-decor-slots.md`.

- 첫 출시 상점: 캐릭터 아이템만 (액세서리 6, 의상 4, 머리 모양 8, 머리 색 7). 머리 모양과 머리 색은 따로 고르고, 산 색은 모든 머리 모양에 쓴다 (2026-10-31 결정). 책상 소품과 공용 가구는 방 꾸미기 슬롯과 함께 올린다.
- 몸은 하나이고 처음 꾸미기에서 남녀를 고른다. 남녀는 눈매(남자는 속눈썹 없음)와 기본 머리 모양, 기본 옷만 바꾸고, 아이템은 누구나 쓴다 (2026-10-31 결정).
- 가입 시 기본 몸, 눈 색 7종 (보라, 검정, 갈색, 호박색, 초록, 파랑, 회색), 머리 모양 2종 (단발, 짧은 머리), 머리 색 3종 (검정, 밤색, 라벤더), 의상 3종 (교복 치마, 교복 바지, 세이지 옷) 무료. 처음 모습은 여자는 단발과 교복 치마, 남자는 짧은 머리와 교복 바지, 둘 다 검은 머리와 검은 눈, 환영 선물 120코인 (우편). 입어 보기 가능, 환불과 되팔기 없음.

| 품목 | 가격 (코인) | 공부 시간 환산 |
|---|---|---|
| 액세서리 | 120~300 | 2~5시간 |
| 머리 색 | 300 | 5시간 |
| 의상과 머리 모양 | 600~1500 | 10~25시간 |
| 책상 소품 | 180~600 | 3~10시간 |
| 공용 가구 (방장) | 900~3000 | 15~50시간 |

## 아트
- 메이플스토리 수준의 2D 도트 스프라이트로 다시 만든다 (2026-10-30 결정: 24×32 고정 32색 시범이 얼굴을 살리지 못해 크기를 2배로 키우고 색 제한을 풀었다). 현재 원본 이미지는 그대로 보관하고 구조와 배치의 기준으로만 쓴다.
- 방 672×432를 1배로 표시 (2026-10-30 결정: 2배는 1280 화면의 방 무대 폭 약 880px에 들어가지 않음). 원본 회사 이미지의 x 0~1340, y 60~922 범위(제목줄과 오른쪽 타이머, 할 일, 음악 패널 제외)를 따른다. 캐릭터 56×72도 1배라 방 폭 대비 비율이 지금 화면(약 7.8%)과 같다.
- 캐릭터 56×72 (캐릭터 키 약 70px, 2등신), 가구와 소품은 16픽셀 격자.
- 색 수 제한 없음. 반투명 픽셀은 실루엣 가장자리(완전 투명 픽셀과 맞닿은 곳)에만 쓰고 안쪽은 불투명.
- 캐릭터: 머리카락과 옷이 없는 기본 몸을 먼저 만들고, 같은 몸에 머리카락이나 옷 하나만 더한 그림과의 차이로 부품을 떼어 낸다. 걷기는 같은 뼈대로 만든 4프레임. 생성은 PixelLab, 부품 떼기와 시트 조립, 잡티 정리는 `tools/art/build-character.mjs`. 원본을 줄여 만든 밑그림은 흐려져서 쓰지 않는다. 방: 원본 기준 밑그림 위에 손 보정. 생성 이미지나 자동 변환 결과를 손 보정 없이 쓰지 않는다.
- 자동 검사: 안쪽 반투명 픽셀, 크기 위반, 발 기준점 어긋남을 테스트에서 차단 (`tools/art/validate.mjs`).
- 첫 출시 애니메이션: 4방향 서기, 4방향 걷기 (4프레임), 의자 앉기 (위와 아래 좌석), 소파 휴식. 모든 레이어가 같은 프레임 구성.

## 기술
- React, TypeScript (점진 전환, Supabase 생성 타입 사용), Vite, Vercel.
- Supabase: Postgres, 인증 (Google 먼저, 카카오 다음), Realtime, 행 단위 보안. 개발과 운영 프로젝트 분리, 마이그레이션 파일로 DB 변경 기록.
- React용 MVVM: Model은 React를 모르는 순수 로직과 주입되는 저장소, ViewModel은 커스텀 훅 (TanStack Query와 Realtime 포함), View는 그리기만. 폴더는 `src/features/<기능>/{model,viewmodel,view}`.
- 주소 라우팅 (`/lobby`, `/rooms/:code`, `/records` 등).
- 실시간 이동은 목적지만 전송하고 경로는 각 화면에서 결정적으로 계산. 좌석 경쟁은 DB 제약과 함수가 판정.
- 테스트: Model 단위 테스트, 로컬 Supabase (Docker) 통합 테스트, Playwright 화면 흐름, 픽셀아트 검사. GitHub Actions에서 PR마다 실행, PR마다 미리보기 배포.
- 개인정보: 계정 삭제 시 기록, 할 일, 아이템, 친구 관계 삭제. 방장 권한은 가장 오래 함께한 사람에게, 남은 사람이 없으면 방 삭제. 수집 정보는 로그인 이메일과 화면 이름뿐, 개인정보 처리방침 페이지 제공.

## 작업 원칙
- 로비는 재설계한다(2026-10-30). 캐릭터는 레이어 부품으로 그려 꾸미기를 그대로 반영하고, 배경 장면과 패널은 서로 분리된 부품으로 둔다.
- UI 문구에 가운뎃점을 쓰지 않는다. 기존 문구는 해당 화면을 작업할 때 바꾼다.
- 프로세스는 rigor minimal: 이 브리프와 스토리로 진행하고 GDD, 아트 바이블, ADR은 쓰지 않는다.
