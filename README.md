# 모여공부 (moyeogongbu)

픽셀아트 스타일의 PC 웹 온라인 스터디 서비스입니다. React + Vite로 만든 프런트엔드 로컬 데모입니다. 현재 2단계로 회사 스터디룸 입장과 캐릭터 이동을 제공합니다.

## 실행하기

Node.js 22.12 이상(현재 환경: 24)과 npm이 필요합니다.

```bash
cd /workspace/moyeogongbu
npm ci
npm run dev -- --host 0.0.0.0 --port 4173 --strictPort
```

일반 PC에서는 터미널에 표시되는 로컬 주소를 브라우저로 열면 됩니다. 1280px 이상 PC 화면을 권장하며, 최소 레이아웃 너비는 980px입니다.

```bash
npm run build    # dist 폴더에 배포용 파일 생성
npm run preview  # 빌드 결과 실행
npm test         # 실행 중인 앱의 브라우저 기능 검사
```

테스트는 개발 서버가 4173 포트에서 실행 중이어야 합니다. 기본 Chromium 경로는 `/usr/bin/chromium`이며 다른 환경에서는 `CHROMIUM_PATH`로 브라우저 실행 파일 경로를 지정하세요. `APP_URL`로 테스트할 서버 주소도 바꿀 수 있습니다.

## 이번 버전에서 가능한 것

- 프로필과 빠른 입장, 할 일, 공지, 친구 패널이 있는 로비
- 스터디룸·공용 스터디카페·캐릭터 꾸미기·상점·공부 기록·친구 목록·가이드 화면 전환
- 테마 공간 둘러보기, 할 일 추가와 완료 체크, 닉네임 수정
- 기본 캐릭터 색상 미리보기와 적용
- 코인 차감과 중복 구매 방지가 있는 상점 체험
- 우편함·알림·설정 창 열기와 닫기 (Escape 키 지원)

상점과 캐릭터 꾸미기는 처음 접속하면 열리지 않습니다. 로비에 커다란 타이머나 급여 명세서는 배치하지 않았습니다.

## 아직 연결하지 않은 기능

로그인, 데이터베이스, 멀티플레이, 실시간 친구 상태, 채팅과 실제 공부 시간 기록은 구현하지 않았습니다. 친구와 공지는 예시 데이터입니다. 변경한 닉네임, 할 일, 구매와 꾸미기 상태는 **새로고침하면 초기화됩니다**. 달력은 첨부 디자인의 장식용 날짜입니다.

만든 방 목록은 이 브라우저의 localStorage에 저장됩니다. 실제 공부 시간 기록은 아직 없습니다. 다음 단계는 임시 좌표 검토와 방향·동작별 정식 캐릭터 스프라이트 연결입니다.

## 파일 안내

- `src/main.jsx`: 화면과 기본 상호작용
- `src/styles.css`: PC 레이아웃, 종이 질감 패널, 색상
- `public/assets/`: 생성한 로비 배경·캐릭터 및 업로드된 회사 스터디룸 공식 원본
- `tests/app.test.mjs`: Chromium으로 메뉴와 주요 기능을 확인하는 테스트

폰트는 Gowun Dodum / Gowun Batang(패키지 포함, OFL), 아이콘은 Phosphor Icons(MIT)를 사용합니다. 로비 배경과 캐릭터는 참고해 생성한 에셋이므로 원본과 세부 모양은 다릅니다. 회사 스터디룸 이미지는 사용자가 업로드한 원본입니다. 회사 빠른 입장 카드는 업로드된 공식 원본을 그대로 표시하고, 학교는 원본이 없어 임시 문구를 표시합니다. 로비 배경은 재사용하지 않습니다.


## 빠른 입장 미리보기 교체

회사 공식 원본은 `public/assets/company-study-room.png.png`에 보관되어 있고, 회사 카드에 연결되어 있습니다. 원본 파일은 수정하지 않습니다. 학교 원본은 아직 없으며 임의로 이미지를 생성하지 않았습니다.

1. 확정한 파일을 `public/assets/rooms/office.png`, `public/assets/rooms/school.png`에 넣습니다(폴더가 없으면 생성).
2. `src/roomPreviews.js`에서 각 `src: null`을 각각 `src: "/assets/rooms/office.png"`, `src: "/assets/rooms/school.png"`로 바꿉니다. 다른 파일명도 사용 가능합니다.
3. 카드 크기와 입장 동작은 그대로 유지됩니다. 미등록 또는 로딩 실패 시 임시 문구를 표시합니다.

이 설정은 로비의 빠른 입장 카드만 제어합니다. 스터디룸 내부 화면은 이번 변경 범위에 포함되지 않습니다.


## 2단계: 회사 스터디룸 사용하기

1. 왼쪽 **스터디룸** 메뉴를 누르면 방 목록이 열립니다. 로비로 돌아갈 때는 상단 로고 또는 목록의 돌아가기 버튼을 사용합니다.
2. 방 이름을 입력해 만들고 **만든 방 입장하기** 또는 내가 만든 방의 **입장하기**를 누릅니다. 로비 회사 빠른 입장은 내가 만든 첫 방 또는 기본 초대 예시 방으로 연결됩니다.
3. 초대받은 방은 `함께하는 회사` 예시가 제공됩니다. **초대 코드 `MOYEO6`** 또는 만든 방의 코드를 입력하면 해당 로컬 방에 입장합니다. 다른 브라우저의 코드는 인식하지 않습니다.
4. 출입구에 등장한 캐릭터를 움직이려면 좌석 번호를 누릅니다. 위쪽 1·2·3번, 아래쪽 4·5·6번입니다. 키보드 이동이나 바닥 자유 이동은 없습니다.
5. **휴식하기**는 왼쪽 소파, **공부 재개하기**는 마지막 선택 좌석으로 이동합니다. **퇴근하기**는 출입구까지 이동한 뒤 로비로 돌아갑니다.

방은 최대 6석 모델이며 현재 실제 참여자는 한 명입니다. 방 목록만 브라우저에 저장하고, 좌석 점유와 캐릭터 상태는 퇴장·새로고침 시 초기화합니다. 서버, 계정, 실제 초대 전송, 동시 접속, 공부 시간·급여 기록은 구현하지 않았습니다.

### 원본과 임시 처리

- 회사 배경 `public/assets/company-study-room.png.png`와 기존 로비 캐릭터 `public/assets/avatar.png`는 수정하지 않았습니다.
- 회사 원본 전체를 3:2 비율로 표시합니다. 원본에 그려진 타이머·할 일·음악과 참가 인원은 이미지의 일부이고 실제 컨트롤/상태가 아닙니다. 실제 동작 버튼과 참여 인원은 이미지 밖에 있습니다.
- 배경에 여섯 캐릭터가 이미 있어, 사용자 결정대로 **착석하면 이동 캐릭터를 숨기고 원본 인물과 ‘내 자리’ 배지로 임시 착석을 표현**합니다. 원본 인물 여섯 명이 실제 접속자를 뜻하지 않습니다.
- 이동·휴식에는 보라색 리본, 긴 머리, 크림색 상의, 보라색 치마를 참고해 별도 생성한 임시 캐릭터를 사용합니다. 정식 디자인이 아닙니다.
- 실제 걷기/방향/앉기 프레임이 없어 정면 이미지 한 장을 좌우 반전·흔들기·축소해 표현합니다. 감소된 모션 설정에서는 흔들기를 생략합니다.
- 통로와 의자 위치는 사용자가 승인한 **임시 상대 좌표**입니다. 책상 몸체를 가로지르는 직선 이동 대신 좌측 통로와 위쪽 뒤 통로·두 책상 줄 사이의 좁은 경계를 따라 이동합니다. 좁은 중앙 통로, 위쪽 가구 경계, 소파와 가려진 의자 위치는 추가 검토가 필요하며 픽셀 단위 충돌/가림 처리는 아직 없습니다.

### 구현 위치

- `src/study/rooms.js`, `useRooms.js`: 방 모델(최대 6석), 로컬 저장, 코드 생성
- `src/study/RoomList.jsx`: 방 생성·목록·초대 코드 입장
- `src/study/companyLayout.js`: 출입구·좌석·소파·통로·클릭 위치를 모은 유일한 좌표 설정
- `src/study/pathfinding.js`: 통로 그래프 최단 경로
- `src/study/useCharacterMovement.js`: 이동·착석·휴식·퇴장 상태와 프레임별 좌표
- `src/study/CharacterSprite.jsx`, `characterSprites.js`: 이동 로직과 분리된 이미지 렌더링. 방향/동작별 경로와 프레임 배열 교체 가능
- `src/study/CompanyRoom.jsx`: 방·선택 좌석·실제 점유 좌석·캐릭터 상태 연결

실제 멀티플레이를 도입할 때는 방/좌석 서버 상태와 충돌 방지, 사용자별 캐릭터 목록이 필요합니다. 정식 앉기 스프라이트로 전환하려면 원본에 합쳐진 인물을 별도 레이어로 분리하는 디자인 협의도 필요하며, 원본은 계속 별도로 보관합니다.
